# Fix "nothing stays after upload": wire index.html to app.js + styles.css

**Files changed:**
- frontend/index.html

The uploaded-document results disappeared because `frontend/index.html` still contained the old inline-script skeleton and never loaded the real frontend (`app.js` + `styles.css`); those files existed but were dead code. The inline skeleton also had no error handling, so any failed step left the page blank with no message — looking like "nothing stays." I confirmed the backend was healthy by exercising `POST /parse` -> `POST /scrub/{id}` -> `POST /score` directly against the running server; the in-memory `store.DOCS` state persisted correctly across requests, so the bug was entirely in the view layer. Rewrote `index.html` to link `styles.css`, load `app.js` as an ES module, and provide exactly the markup `app.js` drives: the error banner (`#error`), uploader (`#pdf`, `#filename`, `#go`), the 4-step `.stepper`, the privacy gate (`#gate`, `#gate-status`, `#people`, `#accept`, `#send`), the heatmap with PDF.js canvas (`#heat`, `#tiles`, `#canvasWrap`, `#pageCanvas`, `#detail`), and the LLM side-by-side view (`#llmview`, `#pages`). Verified over HTTP that `/` now returns the new page referencing both assets and that `/app.js` and `/styles.css` serve with correct content types. No backend code changed. The legacy skeleton remains preserved as `frontend/index.skeleton.html`.

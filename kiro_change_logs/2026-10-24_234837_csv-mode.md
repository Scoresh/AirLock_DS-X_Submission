# CSV scrubbing mode

**Files changed:**
- `backend/app/csv_mode.py` (new), `backend/app/main.py` (`POST /csv/scrub`, `GET /csv/{id}/download`), `backend/app/risk_config.json` (`csv` section)
- `backend/scripts/scrub_csv.py` (new), `frontend/index.html`, `frontend/app.js`, `frontend/styles.css`, `tests/test_csv_mode.py` (new)

Researchers can now scrub a whole data table, not only a PDF. Each column is classified from the config: direct identifiers become tokens such as [ID_00042], quasi-identifiers are generalized (major to field, rare categories to "Other", dates to years, redundant codes removed) and other columns are kept. The key file keeps the tokens and the original generalized values so the exact table can be restored; it stays in keys/. The response reports the k distribution before and after. On the organizers' data (aggregates only) unique rows fall from 15.1% to 2.7% and low-risk rows rise from 51.2% to 81.8%. The intake page has a "Working with a data table instead?" section with the report and a download. Tests cover the exact round trip, tokens, generalization, risk and the endpoints; 37 pass.
